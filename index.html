Լոգարիթմները ծրագրավորման մեջ

Ինչպե՞ս է մեկ մաթեմատիկական գաղափար օգնում որոնել միլիոնավոր տվյալների մեջ, կառուցել արդյունավետ ալգորիթմներ և հասկանալ համակարգիչների աշխատանքը։

Սկսել ուսումնասիրությունը ↘Փորձարկել գործիքները

11-րդ դասարանի հետազոտական նախագիծ · Ինտերակտիվ ուսումնական հարթակ

log₂(1 048 576) = 20Մեկ միլիոնից ավելի հնարավորություններից՝ մոտ 20 բաժանումով որոնում։
01 / ՄԱԹԵՄԱՏԻԿԱԿԱՆ ՀԻՄՔԵՐ

Ի՞նչ է լոգարիթմը

Լոգարիթմը պատասխանում է այն հարցին, թե ինչ աստիճան բարձրացնենք հիմքը՝ տվյալ թիվը ստանալու համար։

Սահմանում

logₐ(x) = y ⇔ aʸ = x

Այստեղ a-ն հիմքն է, x-ը՝ լոգարիթմի արգումենտը, իսկ y-ը՝ արդյունքը։ Պայմաններն են՝ a > 0, a ≠ 1, x > 0։

Օրինակ՝ log₂(8)=3, քանի որ 2³=8։

Հիմնական հատկություններ

logₐ(xy)=logₐx + logₐy
logₐ(x/y)=logₐx − logₐy
logₐ(xʳ)=r·logₐx
logₐx = logᵦx / logᵦa

Վերջին բանաձևը կոչվում է հիմքի փոփոխման բանաձև։

Տասական լոգարիթմ

log₁₀(x)

Հիմքը 10 է։ Օգտակար է տասնորդական կարգերը և մեծությունների սանդղակները նկարագրելիս։

Բնական լոգարիթմ

ln(x)=logₑ(x)

Հիմքը e ≈ 2.71828 է։ Հաճախ հանդիպում է մաթեմատիկական մոդելներում, աճի և փոփոխության խնդիրներում։

Ցուցչային կապը

y=aˣ ⇔ x=logₐ(y)

Լոգարիթմական և ցուցչային ֆունկցիաները փոխադարձ հակադարձ են։ Նրանց գրաֆիկները համաչափ են y=x ուղղի նկատմամբ։

Լոգարիթմական ֆունկցիայի հատկությունները

  • Սահմանման տիրույթ՝ x>0։
  • Արժեքների բազմություն՝ բոլոր իրական թվերը։
  • Գրաֆիկն անցնում է (1,0) կետով։
  • Եթե a>1՝ ֆունկցիան աճող է։
  • Եթե 0<a<1՝ ֆունկցիան նվազող է։
02 / ՀԱՄԱԿԱՐԳՉԱՅԻՆ ԳԻՏՈՒԹՅՈՒՆ

Ինչո՞ւ են լոգարիթմները կարևոր ծրագրավորման մեջ

Ալգորիթմի արագությունը կախված է ոչ միայն համակարգչից, այլև խնդրի լուծման քայլերի քանակից։

Ժամանակային բարդություն

Ժամանակային բարդությունը նկարագրում է, թե ինչպես է ալգորիթմի գործողությունների քանակը աճում մուտքային տվյալների n չափի մեծացման հետ։ Big O գրառումը տալիս է աճի վերին ասիմպտոտիկ գնահատական՝ անտեսելով հաստատուն գործակիցներն ու փոքր անդամները։

T(n) = O(log n)

Սա նշանակում է, որ n-ը մեծանալիս քայլերի թիվն աճում է շատ դանդաղ։ Եթե խնդրի չափը կրկնապատկվում է, ապա լոգարիթմական քայլերի թիվն ավելանում է մոտ մեկով՝ նույն հիմքի դեպքում։

Ինչպե՞ս է առաջանում O(log n)-ը

Երբ յուրաքանչյուր քայլից հետո որոնման մնացած տիրույթը փոքրանում է հաստատուն բաժնով, օրինակ՝ երկու անգամ, k քայլից հետո մնում է մոտավորապես n/2ᵏ տարր։

n / 2ᵏ ≤ 1 ⇒ 2ᵏ ≥ n ⇒ k ≥ log₂(n)

Ուստի անհրաժեշտ քայլերի թիվը համեմատական է log₂(n)-ին։

Որոնում

Տեսակավորված զանգվածում Binary Search-ը ամեն քայլում հեռացնում է հնարավորությունների մոտ կեսը։

Ծառեր

Հավասարակշռված որոնման ծառի բարձրությունը մոտավորապես log₂(n) է, ուստի որոնումն ու թարմացումը հաճախ O(log n) են։

Տվյալների բազա

Ինդեքսները, օրինակ B-tree ընտանիքի կառուցվածքները, օգնում են տվյալների մեծ հավաքածուներում որոնել՝ առանց բոլոր տողերը հերթով դիտարկելու։ Իրական ծախսը կախված է ինդեքսից և հարցումից։

Կարևոր տարբերակում

O(log n)-ը չի նշանակում, որ ցանկացած ծրագիր, որտեղ կա log ֆունկցիա, աշխատում է լոգարիթմական ժամանակում։ Բարդությունը որոշվում է ալգորիթմի գործողությունների կառուցվածքով։ Նույնպես՝ O(log n) սովորաբար նկարագրում է աճի կարգը, ոչ թե ճշգրիտ վայրկյանները։

Օրինակ՝ Binary Search-ը պահանջում է նախապես տեսակավորված տվյալներ։ Եթե տեսակավորումը պետք է կատարել սկզբից, այդ նախապատրաստման արժեքը նույնպես պետք է հաշվի առնել։
03 / ԱԼԳՈՐԻԹՄՆԵՐԻ ՀԱՄԵՄԱՏՈՒԹՅՈՒՆ

O(log n), O(n), O(n²)

Ընտրիր տվյալների քանակը և համեմատիր երեք տեսակի աճը։ Գրաֆիկը ցույց է տալիս պայմանական գործողությունների քանակը, ոչ թե իրական վայրկյանները։

Լոգարիթմական · log₂(n)
10

Յուրաքանչյուր քայլում տիրույթը մոտ կես է դառնում։

Գծային · n
1 000

Ամեն տարրը կարող է ստուգվել մեկ անգամ։

Քառակուսային · n²
1 000 000

Երկու ներդրված ցիկլերի օրինակային աճ։

Նշում․ քառակուսային արժեքը գրաֆիկում նորմավորված է, որպեսզի երեք կորերն էլ տեսանելի լինեն։ Թվային համեմատության քարտերում ցուցադրվում են n, log₂(n), n² արժեքները։

04 / ԻՆՏԵՐԱԿՏԻՎ ԱԼԳՈՐԻԹՄ

Փորձարկիր Binary Search-ը

Ալգորիթմը աշխատում է տեսակավորված ցուցակի վրա։ Ամեն քայլում ստուգում է միջին տարրը և պահում միայն այն կեսը, որտեղ կարող է գտնվել որոնվող թիվը։

Սեղմիր «Սկսել նոր որոնում»։

Կանաչը ցույց է տալիս որոնման ընթացիկ տիրույթը, կապույտը՝ միջին տարրը։

mid = ⌊(left + right) / 2⌋

Օրինակային ցուցակը 1-ից 31 ամբողջ թվերն են։ Առավելագույնը պահանջվում է մոտ ⌈log₂(32)⌉ = 5 ստուգում՝ այս 31 տարրերի դեպքում։

05 / ՄԱԹԵՄԱՏԻԿԱԿԱՆ ՓՈՐՁԱՍԵՆՅԱԿ

Փոխիր հիմքը, հաշվիր, ուսումնասիրիր

Երկու գործիք՝ լոգարիթմի հաշվիչ և փոփոխվող հիմքով գրաֆիկ։

Լոգարիթմի հաշվիչ

log₂(64) = 6

Հաշվարկը կատարվում է հիմքի փոփոխման բանաձևով՝ ln(x)/ln(a)։

Փոփոխվող հիմքով գրաֆիկ

Քանի որ a>1, գրաֆիկը աճող է։

06 / ԳՈՐԾՆԱԿԱՆ ԾՐԱԳՐԱՎՈՐՈՒՄ

Python-ի օրինակներ

Ստորև բերված են պարզ օրինակներ, որոնք ցույց են տալիս լոգարիթմների և ալգորիթմների կապը։

1. Լոգարիթմ հաշվելը

import math

print(math.log2(64))   # 6.0
print(math.log10(100)) # 2.0
print(math.log( math.e )) # 1.0

Python-ի math մոդուլում log(x)-ը բնական լոգարիթմն է, log2(x)-ը՝ հիմք 2-ով, իսկ log10(x)-ը՝ հիմք 10-ով։ Արգումենտը պետք է լինի դրական։

2. Binary Search

def binary_search(items, target):
    left, right = 0, len(items) - 1

    while left <= right:
        mid = (left + right) // 2

        if items[mid] == target:
            return mid
        if items[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1

Յուրաքանչյուր կրկնության ընթացքում որոնման միջակայքը փոքրանում է մոտ երկու անգամ։ Ժամանակային բարդությունը O(log n), իսկ լրացուցիչ հիշողության բարդությունը՝ O(1) է՝ այս կրկնողական տարբերակի համար։

3. Երեք աճերի գաղափարը

# O(n): մեկ անցում
for item in items:
    process(item)

# O(n²): յուրաքանչյուրի հետ համեմատել բոլորը
for a in items:
    for b in items:
        compare(a, b)

# O(log n): միջակայքը կիսել
while left <= right:
    mid = (left + right) // 2
    # հեռացնել միջակայքի կեսը

Կոդի բարդությունը որոշվում է ցիկլերի և խնդրի չափի փոխազդեցությամբ։ Երրորդ օրինակը ամբողջական ալգորիթմ չէ, այլ լոգարիթմական քայլերի գաղափարի ուրվագիծ։

Գործնական դիտարկում

Եթե n=1 000 000, ապա log₂(n)≈19.93, այսինքն՝ ամբողջական կիսման մոտեցմամբ պետք է մոտ 20 մակարդակի քայլ։ Գծային որոնումը վատագույն դեպքում կարող է ստուգել մինչև 1 000 000 տարր։

Սա գործողությունների քանակի տեսական համեմատություն է։ Իրական ժամանակը կախված է սարքից, տվյալների տեղակայությունից, ծրագրի իրականացումից և այլ գործոններից։

Անվտանգության և կայունության համար կոդը գործարկվում է դիտարկիչի մեկուսացված Python միջավայրում։ Pyodide-ը առաջին անգամ բեռնվելու համար ներբեռնում է անհրաժեշտ ֆայլերը, ուստի ինտերնետ կապ է պահանջվում։ Այնուհետև նույն դիտարկիչում միջավայրը կարող է մնալ պահված քեշում։
08 / ԿԻՐԱՌՈՒԹՅՈՒՆՆԵՐ

Որտե՞ղ ենք հանդիպում լոգարիթմներին

Տվյալների բազաներ

Ինդեքսները կարող են արագացնել որոնումը։ SQLite-ի բացատրական նյութը ցույց է տալիս, թե ինչպես են ինդեքսներն օգտագործվում որոնման և տեսակավորման ժամանակ։

Տվյալների կառուցվածքներ

Հավասարակշռված ծառերում բարձրությունը պահվում է լոգարիթմական կարգի սահմաններում, ինչն օգնում է որոնման և փոփոխման գործողություններին։

Տեղեկատվության չափում

Տեղեկության տեսության մեջ log₂-ը կիրառվում է բիթերով տեղեկատվության և անորոշության չափման համար։ Օրինակ՝ հավասար հավանականությամբ 8 տարբերակներից մեկի ընտրությունը պարունակում է 3 բիթ տեղեկություն։

Կոմպրեսիա

Որոշ սեղմման մեթոդների տեսական հիմքում հանդիպում են հավանականությունների լոգարիթմները և տեղեկատվական էնտրոպիան։ Լոգարիթմը ինքնին ֆայլ չի սեղմում, այլ օգնում է գնահատել տեղեկատվության չափը։

Համակարգչային ցանցեր

Որոշ ցանցային ալգորիթմներ և ծառային որոնումներ օգտագործում են լոգարիթմական խորություն կամ փուլերի քանակ։ Կիրառությունը կախված է կոնկրետ արձանագրությունից և կառուցվածքից։

Գիտական հաշվարկներ

Լոգարիթմական սանդղակները հարմար են շատ լայն միջակայքով մեծություններ ներկայացնելու համար, իսկ ln-ը հաճախ հանդիպում է հավանականության և մաթեմատիկական մոդելներում։

09 / ԳԻՏԵԼԻՔՆԵՐԻ ՍՏՈՒԳՈՒՄ

Փոքրիկ թեստ

Պատասխանիր հարցերին և ստուգիր՝ որքան լավ ես հասկացել թեման։

1. Ի՞նչ է նշանակում log₂(16)։

2. Binary Search-ը ինչո՞ւ է O(log n)։

3. Ո՞ր պայմանն է պարտադիր դասական Binary Search-ի համար։

4. Ո՞րն է Python-ում բնական լոգարիթմ հաշվելու կանչը։

5. Եթե տվյալների քանակը 1024 է, ապա log₂(1024)-ը հավասար է՝

Ընտրիր պատասխանները և սեղմիր ստուգելու կոճակը։
10 / ԱՄՓՈՓՈՒՄ

Եզրակացություն

Հետազոտությունը ցույց է տալիս, որ լոգարիթմը դպրոցական մաթեմատիկայի և ծրագրավորման միջև իրական կապող օղակ է։ Մաթեմատիկայում այն հակադարձում է ցուցչային գործողությունը, իսկ ալգորիթմներում նկարագրում է այն դեպքերը, երբ յուրաքանչյուր քայլում խնդրի չափը փոքրանում է հաստատուն գործակցով։

Binary Search-ը այդ կապի պարզ և տեսանելի օրինակն է․ տեսակավորված տվյալների վրա այն կիսում է որոնման միջակայքը, ինչի պատճառով անհրաժեշտ քայլերի քանակը աճում է log₂(n)-ի կարգով։ Նման աճ հանդիպում է նաև հավասարակշռված ծառերի և ինդեքսների որոշ գործողություններում։

Ուստի ծրագրավորողին լոգարիթմները պետք են ոչ միայն բանաձևեր հաշվելու, այլև ալգորիթմներ վերլուծելու, տվյալների կառուցվածքներ ընտրելու և մեծ խնդիրների համար արդյունավետ լուծումներ նախագծելու համար։

Հետազոտության գլխավոր բացահայտում․ երբ խնդրի չափը բազմապատկվում է, լոգարիթմական ալգորիթմի քայլերի քանակը աճում է շատ ավելի դանդաղ, քան գծային կամ քառակուսային ալգորիթմներինը։
11 / ՎՍՏԱՀԵԼԻ ԱՂԲՅՈՒՐՆԵՐ

Օգտագործված գրականություն

Ստորև բերված են թեմայի համար օգտագործված ստուգելի տեխնիկական աղբյուրներ։

  1. Python Software Foundation, Python-ի math մոդուլի պաշտոնական փաստաթղթեր։
  2. CP-Algorithms, Binary Search — կիսման սկզբունքի և O(log n) գնահատման բացատրություն։
  3. SQLite, Query Planning — տվյալների բազայի ինդեքսների և որոնման պլանավորման մասին։
  4. OpenDSA, OpenDSA ուսումնական նյութեր — տվյալների կառուցվածքներ և ալգորիթմների վերլուծություն։
  5. Ս. Լ. Սալաս, Է. Հիլ, Գ. Էտգեն, Calculus: One and Several Variables — ցուցչային և լոգարիթմական ֆունկցիաների մաթեմատիկական հիմքեր (ուսումնական գրականություն)։

Վեբ աղբյուրների հասանելիությունն ու բովանդակությունը կարող են ժամանակի ընթացքում թարմացվել։ Տեսական բացատրությունները նախագծում ներկայացված են դպրոցական մակարդակին համապատասխանեցված ձևով։
